# v11 — 깊이 스캔으로 고정 v5/v10 전환

## 요청과 방법

평탄 구간에서는 v5, 거친 구간에서는 v10 anchored를 사용하는 사용자의 제안을
시험한다. **새 정책 학습은 없다.** v5와 v10의 가중치, 관측·행동 인터페이스,
물리·보상·종료 조건은 변경하지 않는다. v10의 세 학습 seed 42/43/44를 모두
사용하며, 좋은 seed만 선택하지 않는다.

- v5: `rough_v5_portal_rehearsal4_seed43/model_round_4.pt`의 60D actor.
  각 v10 checkpoint 안에 저장된 teacher와 원본의 모든 actor tensor가 정확히 같다.
- v10: 기존 88D anchored actor. 두 정책 모두 같은 현재 상태를 입력받는다.
- 선택기: 기존 **825개 이상적 높이 ray scan**만 사용한다. 지형 이름·난이도·맵
  좌표·미래 궤적을 선택기에 주지 않는다. 실제 RGB-D 카메라 검증은 아니다.
- 전방 ROI: 몸체 기준 x=0~2m, |y|≤1m. 복귀 판단 ROI는 뒤쪽까지 포함한
  x=-1.2~2m, |y|≤1.1m. 높이 q95−q05와 인접 높이차의 q95를 사용한다.
- 선택된 `cautious` 기준: 높이 범위 ≥0.12m **또는** 인접 차 ≥0.08m가
  2프레임 연속 관측되면 v10을 요청한다. 복귀 기준은 두 값 모두 진입 기준의
  0.6배 이하가 0.3초 유지되는 경우다. 최소 유지 시간은 0.5초다.
- 요청 전환 시 0.15초 동안 `action=(1-alpha)*v5+alpha*v10`으로 선형 전환한다.
  이는 동작 불연속을 완화하는 휴리스틱이지, 안정성이나 낙상 방지의 보장이 아니다.
- 유효 ray와 인접쌍 비율이 각각 90% 미만이면 불확실로 처리한다. 현재 요청을
  유지하고 확인 카운터를 초기화한다. 진행 중인 전환은 계속되며, 관측 누락을
  평지로 간주하지 않는다. 에피소드 리셋 때만 초기화하고 portal 이동에서는 유지한다.

## 개발과 동결

[사전 계획](experiment_plans/hybrid_v11.md)에 따라 개발 geometry/reset 51/24에서
v5, v10 seed42, 세 가지 전환 기준을 비교했다. 각 조건은 175환경의 첫 에피소드이며,
아래 통과율의 분모는 평지 25회를 제외한 150회다.

| 개발 조건 | 1타일 | 6타일 | 낙상 | 레인 이탈 |
|---|---:|---:|---:|---:|
| v5 | 122/150 | 60/150 | 21/150 | 2/150 |
| v10 seed42 | 129/150 | 69/150 | 18/150 | 1/150 |
| hybrid cautious (0.12/0.08m) | 133/150 | 68/150 | 16/150 | 0/150 |
| hybrid balanced (0.18/0.12m) | 130/150 | 69/150 | 19/150 | 0/150 |
| hybrid selective (0.27/0.18m) | 128/150 | 68/150 | 22/150 | 0/150 |

사전 순서인 1타일 성공이 많은 순 → 낙상이 적은 순 → 레인 이탈이 적은 순 →
6타일 성공이 많은 순으로 `cautious`를 선택했다.
이것은 **개발 결과이지 일반화 증거가 아니다.**
세 후보가 모두 기준선보다 나빠도 같은 규칙으로 하나를 선택하도록 정했다.
875개 개발 에피소드의 독립 재계산·선택 규칙·초기 상태 일치 검증이 통과했다.

선택 후 63개 소스/계획/테스트와 4개 모델의 SHA256을 동결했다. 기존 v10의 53개
소스/계획은 그대로다. 동결 뒤 새 geometry/reset 68/42와 69/43에서 평가하며,
결과를 보고 임계값을 재조정하지 않는다.

## 비교 조건과 판정

- 16초 주 평가: 지도당 7지형 × 5난이도 × 5회 = 175환경.
  v5는 지도당 한 번만, v10/hybrid는 각각 세 seed를 평가한다.
  총 14파일/2,450개 첫 에피소드. 험지 분모는 v5 300회, 다른 조건 각각 900회다.
- 별도 64초 평가: 최고 난도 1.0 돌다리, 지도당 10환경.
  14파일/140회. v5 20회, 다른 조건 각각 60회. 16초 표본과 합치지 않는다.
- 같은 조건에서 몸체 상태·관절 위치/속도·관측의 초기 SHA가 모든 정책에서
  정확히 같아야 한다. 다르면 평가 묶음을 중단한다.
- 1타일/6타일 성공은 발 도달 범위를 포함한 13.1m/53.1m를 **최종 거리**가 넘고,
  첫 에피소드에 낙상·레인 이탈·world exit가 없는 경우다. 일시적으로 거리를
  넘었다가 넘어지면 성공이 아니다. 자동 리셋 이후 데이터는 집계하지 않는다.
- 교체 조건: 주 평가 1/6타일 비율이 두 단독 정책 이상, 낙상·레인 이탈은 v5 이하,
  모든 에피소드 world exit=0, 평지 낙상은 v5 이하. 추가로 64초 돌다리의 6타일
  비율은 v5보다 높고 낙상은 v5 이하여야 한다. 한 조건이라도 실패하면 v5 유지다.

## 초기 상태 검증 실패와 제한된 운영 재시도

첫 holdout 실행은 세 파일 이후 자동 중단됐다. geometry68/reset42에서 몸체·관절
상태 SHA는 같지만 v5와 v10의 초기 88D 관측 SHA가 달랐다. 뒤이은 세 번의
초기 상태 전용 캡처는 모두 동일했다. 원본 문제 관측은 SHA만 저장되어 있으므로
정확히 어떤 성분이 달랐는지, PhysX 시작 시 힘 관측이 원인인지 **확정할 수 없다**.

[복구 선언](../artifacts/terrain_demo/hybrid_v11/recovery_amendment.json)은 재실행 전에
원본 세 평가와 명령 기록을 해시로 보존하고, 동일 조건의 전체 28평가를 별도
`attempt02/`에서 **한 번만** 실행하도록 정했다. 기존 결과와 섞지 않고, 임계값·모델·
지형·seed·엄격한 초기 SHA 검증을 모두 유지한다. 재실행도 불일치하면 추가 재시도나
검증 완화 없이 기술적 미완료로 판정한다. 이는 성능에 따른 사례 선택이 아니라
데이터 유효성 실패에 대한 운영 재시도이며, 새로 사용하지 않은 holdout이라고
주장하지 않는다. 원본 63개 소스 freeze는 그대로고, 출력 경로만 바꾸는 실행 계층과
독립 감사기의 새 해시는 별도로 고정했다.

## 결과: 전체 교체 기준 FAIL, v5 유지

동일 조건 전체 재시도 attempt02의 28파일/2,590개 첫 에피소드가 완료됐고,
초기 상태·관측의 exact pairing과 독립 수치 감사가 모두 통과했다. 개발875회를
포함한 독립 감사는 3,465개 에피소드/33파일의 배열·집계·판정을 재계산했다.
최초 중단된 세 파일/525회와 정성 영상은 이 수치에 포함하지 않는다.

### 16초 전체 험지

| 정책 | 1타일 | 6타일 | 낙상 | 레인 이탈 |
|---|---:|---:|---:|---:|
| v5 | 263/300 (87.7%) | 133/300 (44.3%) | 23/300 (7.7%) | 0/300 (0.0%) |
| v10 anchored | 814/900 (90.4%) | 438/900 (48.7%) | 67/900 (7.4%) | 11/900 (1.2%) |
| hybrid | 805/900 (89.4%) | 451/900 (50.1%) | 81/900 (9.0%) | 2/900 (0.2%) |

하이브리드의 6타일 통과율은 v5 대비 **+5.8%p**, v10 대비 **+1.4%p**였으나,
낙상률은 v5 대비 **+1.3%p**였다. v10의 레인 이탈 11/900을 2/900으로 줄였지만
v5의 0/300에는 미치지 못했다. 1타일 통과율도 v10보다 낮았다. 따라서 사전 교체
기준 중 `one_vs_v10`, `falls_vs_v5`, `lane_vs_v5`가 실패했다.

### 별도 64초 최고 난도 돌다리

| 정책 | 1타일 | 6타일 | 낙상 | 레인 이탈 |
|---|---:|---:|---:|---:|
| v5 | 7/20 (35.0%) | 1/20 (5.0%) | 7/20 (35.0%) | 2/20 (10.0%) |
| v10 anchored | 25/60 (41.7%) | 15/60 (25.0%) | 26/60 (43.3%) | 8/60 (13.3%) |
| hybrid | 28/60 (46.7%) | 14/60 (23.3%) | 21/60 (35.0%) | 9/60 (15.0%) |

하이브리드는 v5보다 6타일 통과율이 높으면서 낙상률은 같아, 사전 64초 조건 두 개는
통과했다. v10과 비교하면 낙상은 줄었지만 6타일 통과율은 조금 낮고 레인 이탈은
더 많다. 장시간 안정성이 완전히 해결된 것은 아니다. 작은 표본이며 통계적 유의성이나
모든 미지 지형에 대한 우월성을 주장하지 않는다.

### 선택 동작과 seed 차이

- 16초 험지 평균 v10 혼합 비중 **69.99%**, 평지 **0%**. 평지 낙상12/150은
  v5의4/50과 같은 비율이다. world exit는 모든 조건0이었다.
- 16초 험지 전환1,654회; 전환 후0.5초 이내 낙상1회/전체 낙상81회.
  이 수치가 전환의 안전성을 증명하거나 다른 낙상을 전환과 무관하다고 증명하지 않는다.
- 64초 돌다리 v10 혼합 비중 **91.28%**, 전환97회, 전환 직후 낙상0회.
- 16초 seed42/43의 hybrid 6타일 통과는 v10보다 늘었지만 낙상도 늘었다.
  seed44는 낙상이30→25로 줄었지만 6타일은156→155였다. 모든 seed가 개선된 것은 아니다.
- 64초 seed42는 hybrid 낙상6/20, 레인 이탈0/20으로 좋았지만, seed43은
  낙상8/20·레인 이탈5/20이었다. 좋은 seed만 골라 결론내리지 않았다.

**해석:** 지형 인식에 따른 정책 전환은 동작하고 일부 진행·안전 지표에 도움이 된다.
하지만 거칠다는 이유만으로 v10을 고르는 규칙은 상태별 정책 적합성까지 판단하지
못한다. 안정성/진행 상태를 반영하는 전환기나 전환 자체의 학습은 다음 검증 후보이지,
이번에 효과를 입증한 방법이 아니다.

## 추가 정성 영상: 다른 험지 5종

[지형별 세 정책 동시 재생](../artifacts/terrain_demo/hybrid_v11/other_terrains/index.html)에서
계단·불연속 장애물·울퉁불퉁한 지형·경사·파도형 지형을 볼 수 있다.
각 지형은 난이도1.0, geometry68/reset42, v10 정책 seed42이며, 기존 v5와
고정 cautious 하이브리드를 비교한다. 지형별1개씩 총5환경을 동시에 실행하고,
카메라만 바꾸어 각각16초/480프레임/30fps/1280×720 영상15개를 저장했다.
카메라 렌더링 사이에 물리 스텝이나 루트 상태가 바뀌지 않았음을 검사했다.

세 모드의 초기 root/joint/관측 SHA는 정확히 일치하고, 원래63개 고정 소스와
4개 모델은 변하지 않았다. 모든15개 영상의 전체 디코딩과 프레임 수를 확인했다.
좋은 사례를 골라내지 않았으며 낙상·리셋·시간 제한 종료도 그대로 포함한다.
경사 지형의 초기 실패 후 재시작도 성공 사례로 바꾸어 해석하지 않는다.

이 영상은 **정성 자료이며 위 수치나 모델 선택에 추가하지 않는다**.
기존 돌다리 영상은10환경, 추가 영상은5환경으로 배치가 다르다.
실제 RGB-D가 아닌 이상적인 높이 스캔이라는 한계도 같다.
실행 명령·해시·조건·검증은
[새 영상 manifest](../artifacts/terrain_demo/hybrid_v11/other_terrains/manifest.json)에 남겼다.
별도 렌더러는 다음과 같이 **새 출력 경로**에 재현할 수 있다:

```bash
../run-python scripts/render_hybrid_terrains.py --mode hybrid \
  --output-dir outputs/v11_other_terrains_reproduction/hybrid \
  --device cuda:1 --headless --kit_args=--/renderer/multiGpu/enabled=false
```

`--mode v5`와 `--mode v10`도 각각 다른 새 경로를 사용한다. 새 렌더러와
갤러리는 기존 고정 소스 밖에 추가했으며, 소스3개 해시를 촬영 전에 따로 고정했다.

## 한계와 재현

두 지도에서 여러 초기 상태를 평가한 것이며, 수천 개 독립 지도에서 검증한 것이
아니다. 거친 지형이라는 사실만으로 v10이 v5보다 유리한 상태임을 알 수는 없다.
정책 사이의 중간 행동도 따로 학습되지 않았다. 전환 후 0.5초 이내 낙상 통계는
시간적 연관성이지 전환이 낙상을 유발했다는 인과 증거가 아니다.

`scripts/evaluate_hybrid.py`는 기존 평가기나 모델을 바꾸지 않는 별도 진입점이다.
Isaac Lab 환경에서 단일 재현 평가를 새 출력 경로로 실행할 수 있다:

```bash
../run-python scripts/evaluate_hybrid.py --headless --device cuda:1 \
  --mode hybrid --preset cautious --policy-seed 42 \
  --geometry 68 --seed 42 --scenario mixed --seconds 16 --num_envs 175 \
  --phase holdout \
  --checkpoint artifacts/terrain_demo/prior_v10/runs/v10_anchored_seed42/model_749.pt \
  --output outputs/v11_reproduction_hybrid_seed42_geometry68.json
```

전체 runner의 단계는 `develop → freeze → evaluate → horizon → report → videos`이며,
기존 증거를 덮어쓰지 않도록 재실행을 거부한다. 기록이 이미 있는 현재 checkout에서
전체 runner를 다시 실행하지 말고 위 단일 평가의 **새 경로**를 사용한다.
`source_hashes()`는 원래 ignored 계획 경로도 검증하므로 새 checkout에서는
`docs/experiment_plans/{prior_v10,hybrid_v11}.md`의 byte-identical 사본을
각 `outputs/{prior_v10,hybrid_v11}_20260922/PLAN.md`로 복원해야 한다.

269개 CPU 테스트, 소스 컴파일, scan 고정 배치 진단과 GPU smoke가 통과했다.
초기 smoke의 inference tensor 리셋 오류는 개발 전에 수정하고 회귀 테스트를 추가했다.
평지 world exit 누락도 개발 전에 수정했다. 새 의존성·정책 재학습·원격 Git 작업은 없다.
이전 공개 스냅샷의 체크섬 파일은 v11 변경 이후 작업 트리를 검증하는 파일이 아니다.
